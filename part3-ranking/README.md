召回阶段把亿级物品收缩到千级候选后，**排序（Ranking）** 接手了最关键的"精准打分"任务。它的目标是对每一个候选计算最接近真实偏好的预测分数（通常是点击率、转化率等），再按分数排出最优序列。排序是深度网络泛化能力的主战场——本 Part 的五个章节，沿着"如何让模型更强、更灵活、更贴合业务"的脉络，逐层递进。

本 Part 不急于堆砌模型名，而是始终追问一件事：**每个新模型解决了前一个方法的什么不足？** 只有带着"动机"去读，才能在面对真实业务时知道该选哪个模型。

## Tips for This Part

1. **带着"动机"读每个模型。** 遇到新模型先问：它解决了前一层方法的什么不足？结构差异在哪？
2. **公式服务于直觉。** 先理解"为什么这样设计"，再看数学表达；公式只是设计思想的精确写法。
3. **对比着读 Advanced 章节。** 3.2 与 3.3 模型密集、结构相似，用表格横向对比能事半功倍。
4. **动手跑交互演示。** 3.2 与 3.3 各有一个交互式 HTML，用"下一步"直观感受高阶交叉与注意力激活的过程。
